## A complete Flisk landscape, ready to run

This repository is the smallest useful demonstration of the Flisk **Project-Stack-Resource** model: one project, two independently runnable stacks, and four resources described by one `service.json` each.

You declare the service. Flisk discovers the landscape, resolves dependencies, allocates the configured ports, and generates the local Docker, Vite, environment, and TypeScript plumbing inside `.autogenerated/`.

<p align="center">
  <img src="docs/readme-marquee.jpg" alt="service.json, flisk up, .autogenerated, Hono, Vite, Tilt, and Bun" width="100%">
</p>

> ⭐ **This project runs on [Flisk CLI](https://github.com/flisk-sh/flisk).** If it saves you time, [star flisk on GitHub](https://github.com/flisk-sh/flisk) so other developers can find it.

## Run It

> **Repository-pinned CLI (optional):** Run `bun install` from the repository root to install the version pinned in `package.json`. Use `bun run flisk:project` to initialize project config, `bun run flisk:dry-run` to preview startup, or `bun run flisk:up -- <stack>` to start a stack. The global npm and standalone binary installation paths remain available.

### Prerequisites

- [Docker](https://docs.docker.com/get-docker/) is running.
- [Tilt](https://docs.tilt.dev/install.html) is installed.
- [Bun](https://bun.sh/docs/installation) is installed.
- [Flisk CLI](https://github.com/flisk-sh/flisk#installation) is available as `flisk`.

```bash
git clone https://github.com/flisk-sh/flisk-example.git
cd flisk-example
flisk project --yes
flisk up
```

`flisk project --yes` creates the project configuration and discovers the existing `service.json` manifests. Flisk then starts both stacks. Each resource owns its own package and generated development workflow; the root package provides optional project-pinned Flisk CLI scripts.

```bash
# Start one stack only
flisk up identity

# Inspect the running landscape
flisk status

# Stop everything
flisk down
```

## Generation

<p align="center">
  <img src="docs/readme-flow.svg" alt="service.json flows through flisk up into the generated local development configuration." width="100%">
</p>

Every resource owns a compact [`service.json`](services/identity/identity-api/service.json). It describes identity, type, stack, port, dependencies, and health behavior:

```json
{
  "appName": "identity-api",
  "domain": "identity",
  "type": "backend",
  "stack": "identity",
  "port": 4000,
  "dependencies": [],
  "healthCheck": {
    "enabled": true,
    "path": "/health"
  }
}
```

Running `flisk up` turns that manifest into the files needed by Tilt and the selected technology stack.

> [!IMPORTANT]
> Edit `service.json`, `TILT_SERVICE_DEFAULTS.star`, or `TILT_TECH_STACK.star`. Never edit `.autogenerated/`; the next generation pass replaces its contents.

The empty `.autogenerated/` directories remain in Git through `.gitkeep`. Their generated contents stay ignored.

## Project, Stack, Resource

| Level | Meaning in this repository | Command surface |
| --- | --- | --- |
| **Project** | The cloneable landscape rooted at this repository | `flisk up`, `flisk down`, `flisk status` |
| **Stack** | A deployable group such as `identity` or `appointment` | `flisk up identity` |
| **Resource** | One runnable API, app, worker, or infrastructure unit | `flisk resource <name> ...` |

Dependencies are explicit. For example, `identity-app` declares `identity-api`, allowing Flisk to preserve startup intent without hard-coding service orchestration in application code.

## Extend It

Add resources through the CLI, assign them to a stack, and let Flisk regenerate the landscape:

```bash
flisk resource my-api --type backend --stack identity
flisk resource my-app --type frontend --stack identity
flisk stack identity
flisk up identity
flisk status
```

Each resource is independently testable:

```bash
cd services/identity/identity-api
bun install
bun test
bun run typecheck
```

Use the same pattern for the other three resources.
